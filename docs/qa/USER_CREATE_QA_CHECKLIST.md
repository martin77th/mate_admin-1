# 사용자 등록 QA 체크리스트

## 목적
- 사용자 등록 화면(`/users/new`)의 동작을 권한/응답코드/복귀 흐름 기준으로 검증한다.
- 최근 수정된 항목(토큰 컨텍스트 표시, role_name 제어, 409 처리, 자동 검색 복귀)을 확인한다.

## 사전 조건
- 관리자 화면 로그인 완료
- 사용자 목록 페이지(`/users`) 진입 가능
- 사용자 등록 페이지(`/users/new`) 진입 가능

## 공통 확인 항목
1. 콘솔 오류 없음
- `Hydration failed...`
- `Maximum update depth exceeded`

2. 등록 페이지 상단 토큰 정보 표시
- 현재 로그인 토큰 정보
- 역할(Role)
- 테넌트(Tenant)

3. 역할 선택 제어
- admin 계정: 역할 선택 가능
- admin 외 계정: 역할 선택 비활성화 + 안내 문구 표시

## 기능 테스트

### TC-01 사용자 등록 성공(기본 역할 자동)
1. `/users/new` 이동
2. `auth_name`, `auth_password` 입력
3. 역할은 `기본값(자동)` 유지
4. 등록 클릭

기대 결과
- 성공 토스트 노출
- `/users?searchField=auth_name&q=<입력한 auth_name>`로 이동
- 목록에서 해당 사용자 자동 검색 결과 표시

### TC-02 사용자 등록 성공(관리자 계정, 역할 지정)
1. admin 권한 계정 로그인
2. `/users/new` 이동
3. `auth_name`, `auth_password` 입력
4. 역할 `anonymous` 또는 `member` 선택
5. 등록 클릭

기대 결과
- 201 생성 성공
- 성공 토스트 및 목록 복귀

### TC-03 중복 아이디(409 Conflict)
1. 이미 존재하는 `auth_name` 입력
2. 등록 클릭

기대 결과
- 경고 토스트 노출
- 제목: 이미 사용 중인 아이디입니다.
- 메시지: 다른 아이디(auth_name)로 다시 시도해주세요.

### TC-04 필수값 검증
1. `auth_name` 비움 + 등록
2. `auth_password` 비움 + 등록

기대 결과
- 각 필수값 경고 토스트 노출
- API 호출 미발생

### TC-05 비관리자 역할 지정 제약
1. admin이 아닌 계정 로그인
2. `/users/new` 이동
3. 역할 선택 UI 상태 확인
4. 등록 시도

기대 결과
- 역할 선택 UI 비활성화
- role_name 미전송으로 등록 시도
- 서버 정책 내에서 생성 성공 또는 정책 오류 메시지 노출

## 사용자 목록 연계 테스트

### TC-06 자동 검색 복귀
1. `/users/new`에서 새 사용자 등록 성공
2. `/users` 복귀 후 검색 조건 확인

기대 결과
- 검색 조건이 `auth_name`
- 검색어가 등록한 `auth_name`
- 결과 목록에 신규 사용자 노출

### TC-07 서버 페이징
1. `/users`에서 페이지당 개수 10/20/50/100 변경
2. 페이지 이동(처음/이전/번호/다음/마지막) 반복

기대 결과
- API `limit`, `offset` 기준으로 목록 갱신
- 총합계(`total_count`) 기준 페이지 계산 정상
- 행 번호가 전체 순번 기준으로 증가

## 권장 테스트 데이터
- 신규 아이디 샘플: `qa_user_YYYYMMDD_HHMM`
- 중복 테스트용 아이디: 이미 생성된 `auth_name`

## 장애 발생 시 수집 정보
- 로그인 계정(`auth_name`)
- 등록 시점 역할/테넌트 표시값
- 요청 본문(`auth_name`, role_name 포함 여부)
- 응답 상태코드/에러 메시지
- 브라우저 콘솔 에러 전체
