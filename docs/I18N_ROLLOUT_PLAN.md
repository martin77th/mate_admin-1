# MeetMate Admin 다국어(i18n) 반영 계획

## 목표
- 신규 개발은 문자열 하드코딩 없이 i18n 키 기반으로 작성한다.
- 기존 화면은 우선순위에 따라 순차 전환한다.
- 기본 언어는 한국어(`ko`), 보조 언어는 영어(`en`)를 제공한다.

## 적용 원칙
1. 화면/컴포넌트 문자열은 `t('...')`로만 출력한다.
2. 상태코드/역할코드 같은 도메인 라벨도 키 매핑으로 처리한다.
3. 날짜/숫자 포맷은 현재 선택 언어 기준으로 렌더링한다.
4. i18n 미등록 키는 기본 언어(`ko`)로 폴백한다.
5. 신규 페이지는 PR 체크리스트에서 "하드코딩 문자열 없음"을 검증한다.

## 기술 설계
- 리소스: `lib/i18n.ts`
  - `MESSAGES`에 `ko/en` 사전 관리
  - `getMessage`, `normalizeLocale`, `localeToBcp47` 제공
- 런타임 컨텍스트: `components/I18nProvider.tsx`
  - `locale`, `setLocale`, `t` 제공
  - `localStorage(mm_locale)` 영속화
  - `document.documentElement.lang` 동기화
- 루트 주입: `app/providers.tsx` + `app/layout.tsx`

## 반영 순서
1. **기반 완료**
- i18n Provider/사전/locale 저장 구조 적용

2. **핵심 화면 전환**
- 로그인, 공통 레이아웃, 사이드바, 헤더, 대시보드 문자열 키화
- 헤더 드롭다운에 언어 전환(ko/en) 추가

3. **유틸/도메인 라벨 전환**
- 날짜/숫자 포맷 로케일 반영
- 상태/역할 라벨의 언어별 출력 반영

4. **확장 페이지 전환**
- 사용자/미팅/설정 등 신규/기존 페이지를 동일 규칙으로 확장

5. **검증 자동화**
- lint + 간단한 텍스트 스캔으로 하드코딩 문자열 점검
- 키 누락 시 폴백 동작 확인

## 개발 체크리스트
- [ ] 신규 문자열이 `MESSAGES`에 추가되었는가
- [ ] 컴포넌트에서 `t()`를 사용했는가
- [ ] 날짜/숫자가 locale 기반으로 렌더링되는가
- [ ] ko/en 전환 시 레이아웃 깨짐이 없는가
- [ ] 기본 언어 폴백이 동작하는가

## 운영 메모
- 초기에는 `ko`가 기본 언어이며 브라우저 자동 감지는 사용하지 않는다.
- 향후 필요 시 서버/사용자 프로필 기반 언어 설정으로 확장한다.
